## 🧭 Ядро

| № | Воркфлоу | Триггер | Что делает |
|---|---|---|---|
| 0 | Диспетчер писем | 📧 IMAP | Читает входящие, нормализует текст с учётом кодировки, описывает вложения. Gemini относит письмо к одной из восьми категорий, а код переопределяет результат по формальным признакам (отправитель из производства, номер заказа в теме, файл с расчётом). Новая заявка проходит проверку «похоже на заявку», получает атомарный номер и создаёт сделку; если не похожа — руководитель получает уведомление о подозрительной заявке. Расчёт от производства переводит сделку на «Обработку расчёта». Ветки для вопросов о статусе заказа, финансах, технике и логистике заготовлены, но пока без действий. Битая кодировка и сбой модели вызывают алерт. |
| 0 | Авто-рестарт диспетчера | ⏱ ежедневно в 04:00 | Выключает и включает диспетчер через API n8n, проверяет, что он снова активен, при неудаче присылает алерт. Нужен потому, что примерно через месяц без перезагрузки сервера IMAP-триггер тихо переставал получать письма. |
| 0.1 | Обработка ошибок | Error Trigger | Общий обработчик ошибок. Определяет ноду-виновника и формирует два сообщения: разработчику — технические детали и что проверить, руководителю — понятное описание, что сделать вручную. |
| 0.2 | Роутер TG-Бота Контроль задач | 🤖 Telegram | Единая точка входа для всех сообщений TG-Бота Контроль задач. Определяет тип: ответ на задачу, нажатие кнопки, голосовое, меню, упаковка, размещение в производство. Gemini разбирает ответ сотрудника (выполнено или перенос срока), после чего задача закрывается или продлевается в amoCRM, обновляются статусные поля, сделка переводится между этапами, а при неизвестной теме задачи уходит в «Отладку». Показывает меню по роли. Ветка «🏭 Разместить в производство»: по номеру заказа находит сделку, переводит её на «Производство», вызывает воркфлоу 10 и ставит инженеру задачу «Сделать персональную упаковку для деталей» со сроком пять суток и кнопками смены срока до 20 дней. |
| 0a | Заявка через форму n8n | 📝 форма | Трёхшаговая форма на живых данных amoCRM: часть названия компании, выбор компании, контакт и чертежи. Отправляет письмо со служебными маркерами ID на ящик заявок, дальше заявка идёт по обычному конвейеру, но клиент берётся по ID. |

## ⏰ Задачи, голосовые поручения и напоминания

| № | Воркфлоу | Триггер | Что делает |
|---|---|---|---|
| 0.3 | Напоминания: поиск задач | ⏱ каждый час | Находит сделки на этапах с открытыми задачами и по одной передаёт их в 0.4. |
| 0.4 | Напоминания: задачи одной сделки | ↪ из 0.3 | Определяет тему задачи (3D-модель, проверка файлов, связаться с клиентом, выставить КП, персональная упаковка и другие), ведёт счётчик в Data Table и шлёт напоминания уровней 🟢, 🟡, 🔴. Начиная с четвёртого напоминания руководитель получает эскалацию на каждом, пока задача не закрыта. Для задач, которые закрываются кнопками, подсказывает, что ответом можно только перенести срок. |
| 0.5 | Голосовая и текстовая постановка задач | ↪ из 0.2 | Проверяет права автора, скачивает голосовое, расшифровывает и разбирает его в Gemini (с резервной моделью). Выделяет одну или несколько задач, находит сделку через упомянутый контакт или компанию (транслит, нечёткое сравнение), сохраняет черновик в Data Table и показывает карточку подтверждения. |
| 0.6 | Кнопки карточки и создание задач | ↪ из 0.2 | Обрабатывает выбор сделки, исполнителя и срока, подтверждение и отмену. Создаёт задачу в amoCRM (со сделкой или без) и уведомляет исполнителя. |
| 0.7 | Контроль голосовых задач | ⏱ каждый час | Ведёт реестр активных поручений: вопрос о статусе, сигнал руководителю, если исполнитель молчит, предупреждение перед дедлайном, фиксация просрочки, синхронизация с закрытием в amoCRM, отметка потерянных задач. |
| 0.8 | Правка карточки текстом | ↪ из 0.2 | Ответ на карточку свободным текстом: Gemini применяет правку (срок, исполнитель, сделка, текст), карточка перерисовывается. |
| 0.9 | Ответы по голосовым задачам | ↪ из 0.2 | Gemini определяет намерение ответа исполнителя: «готово» закрывает задачу, статус дописывается в неё, перенос срока применяется после подтверждения руководителя. |

## 🏭 Этапы воронки

| Этап | Воркфлоу | Триггер | Что делает |
|---|---|---|---|
| 1. Новая заявка | 1. Обработка письма | 🔔 | Проверка секрета вебхука, получение письма и вложений (zip, 7z, rar, с добором отдельных файлов рядом с архивом), анализ чертежей в Gemini 2.5 Pro (тип чертежа, материал и группа, марка, термообработка и твёрдость, покрытия, квалитет) с паузами и повторами при лимитах API, запись в сделку. Поиск или создание контакта и компании: нечёткое сравнение с порогом 90 % в одном алфавите и 75 % через транслитерацию. Недостающие поля дозаполняются; если данных не хватает, руководитель получает уведомление. Заявки из формы идут в обход поиска, по ID. |
| 2. Файловая структура | 2. Если характеристики есть, собирает `Details.txt` на русском и английском (перевод в Gemini), опросник не нужен. Если нет, формирует ссылку на опросник Tally с параметрами, чтобы форма открывалась предзаполненной, и сохраняет её в Google Sheets; при заявке больше чем на десять деталей вместо этого уведомляет руководителя. Письмо клиенту с опросником отключено заглушкой: по обратной связи клиентов опросник заполняет менеджер. Если не хватает 3D-моделей, ставит задачу инженеру. Когда обе части готовы, переводит сделку на «Проверку наименований». |
| | 3.1 Задача менеджеру по опроснику | ⏱ каждые 15 минут | Изначально — серия из трёх писем-напоминаний клиенту, затем задача менеджеру. Сейчас письма отключены, а счётчик выставлен так, что менеджер сразу получает задачу связаться с клиентом и заполнить опросник, со ссылкой на форму. Механизм писем сохранён для доработки этапа. |

| 4. Проверка наименований | 4. Проверка наименований чертежей и 3D-моделей | 🔔 | Сверка файлов папки заказа с `Details.txt`: комплект PDF + STP + DWG на каждую деталь, нормализация имён с номером детали, удаление дублей и мусора с защитой папок и файлов без расширения. Спорные случаи уходят инженеру задачей, после её закрытия проверка повторяется. Чистый результат переводит сделку на «Расчёт и инженер». |

| 6. Обработка расчёта | 6. Обработка расчёта от производства | 🔔 | Находит письмо с расчётом, выбирает вложение, Gemini извлекает цены из текста, фото, `.xlsx` или `.xls` и сверяет итог с суммой позиций. Цена записывается в сделку и в файл «Расчётная цена» (Google Sheets) в папке заказа, вложения — в `3_Сметы_и_Счета`. Ассистент получает задачу сформировать КП, согласовать наценку и отправить клиенту; если цену распознать не удалось, приходит отдельное уведомление. |

## 🗄️ Хранилища

| Хранилище | Что хранит |
|---|---|
| Data Table `orders` | заказы: номер, сделка, список деталей, статус |
| Data Table `detail_state` | состояние каждой детали: ожидает, в партии, возвращена, принята |
| Data Table `batches` | партии: статус, задачи, активные детали и количества, папка на Google Drive |
| Data Table `bot_drafts` | черновики экранов бота, по пользователю и сообщению |
| Data Table `task_reminders` | счётчики напоминаний по задачам |
| Data Table «реестр поручений» | черновики карточек и активные голосовые поручения |
| SQLite в kp-bot | диалоги, настройки, справочник покупателей, счётчики нумерации, замороженные снимки КП, КП в ожидании чертежей, номера платёжных документов |
| Google Sheets | ссылки на предзаполненные опросники Tally, файлы «Расчётная цена» в папках заказов, учёт замечаний по фотоотчётам и их настройки |
| Google Apps Script | атомарные счётчики номеров заявок и компаний (`LockService`) |
| Приватный репозиторий GitHub | ночные снимки всех воркфлоу |
